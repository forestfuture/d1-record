# Attributes are camelCase; columns are snake_case

**Attribute** names follow JavaScript convention (`userId`, `createdAt`), and D1 columns follow SQL convention (`user_id`, `created_at`). The brief's examples use snake_case everywhere. We map between the two automatically when compiling queries and hydrating rows, and an attribute can name its column explicitly when the automatic conversion is wrong (e.g. acronyms). Every object-style API (`where`, `order`, `pluck`, `foreignKey`, `attributes()`) takes attribute names. Raw SQL fragments are SQL, so they use column names. Changing this after release would break every caller, which is why it's recorded here.
