## 0.2.0

### Minor Changes

- [#151](https://github.com/forestfuture/d1-record/pull/151) [`8bff94a`](https://github.com/forestfuture/d1-record/commit/8bff94a81325d6fa9963223201ce57d08668fefa) Thanks [@christopherstyles](https://github.com/christopherstyles)! - An `sql` fragment that compares a bare `Date`, or a date text string, directly with the column of an attribute stored as a Unix time (`storage: "unixSeconds"` or `"unixMilliseconds"`) now throws `TypeError` where the fragment is used, with the fix in the message. ### Patch Changes

- [#144](https://github.com/forestfuture/d1-record/pull/144) [`9115053`](https://github.com/forestfuture/d1-record/commit/9115053978d0b22504be180d492120b3baf48176) Thanks [@christopherstyles](https://github.com/christopherstyles)! - A `datetime` can be stored as a Unix time in an `INTEGER` column: declare it with `storage: "unixSeconds"` or `"unixMilliseconds"`, as in `ApplicationRecord("posts", { publishedAt: { type: "datetime", storage: "unixSeconds" } })`, to read and write Drizzle's `timestamp` and `timestamp_ms` columns as `Date`s. `d1-record schema`'s notes for a numeric timestamp, and for a `DATETIME` column that defaults to a number, name the override. - [#150](https://github.com/forestfuture/d1-record/pull/150) [`3c960ff`](https://github.com/forestfuture/d1-record/commit/3c960ff9a3148320e6ac358fe293d4d5c965d47f) Thanks [@christopherstyles](https://github.com/christopherstyles)! - `d1-record schema` notes a `DATETIME` column whose default is `CURRENT_TIMESTAMP` or `datetime('now')`, in migrations written by Drizzle or Prisma. That default writes SQLite's date text (`2026-10-12 06:38:30`) where d1-record writes ISO text, and the two sort apart as text.

  The Existing databases guide shows a migration that rewrites a column to d1-record's form, and a `strftime` fragment that compares and orders a column holding both.

- [#147](https://github.com/forestfuture/d1-record/pull/147) [`4e141c0`](https://github.com/forestfuture/d1-record/commit/4e141c0e2d1e3a247de5e072d4ca0398ccd45f7a) Thanks [@christopherstyles](https://github.com/christopherstyles)! - `column("publishedAt").value(date)` is a value of that attribute for an `sql` fragment, written as the attribute stores it. A plain `Date` in a fragment is ISO text, which doesn't compare with an attribute stored as an integer Unix time (`storage: "unixSeconds"`). The value is cast like an assigned one, stays a bound parameter, and is hidden from `onQuery` for a filtered attribute.

- [#144](https://github.com/forestfuture/d1-record/pull/144) [`9656c7b`](https://github.com/forestfuture/d1-record/commit/9656c7b006880751439ef89bd6bc70f1a9cfc719) Thanks [@christopherstyles](https://github.com/christopherstyles)! - A stored date with no time zone, as SQLite's `DEFAULT CURRENT_TIMESTAMP` writes it (`2026-10-12 06:38:30`), now reads as UTC. It was read in the process's time zone, so in Node outside UTC (the console, scripts, tests) it came back hours off. Workers were unaffected, as they run in UTC.

## 0.1.2

## 0.1.0

### Minor Changes

- [`74a956f`](https://github.com/forestfuture/d1-record/commit/74a956ffe1bd9d6b13da117f3fc9d4605edc5b24) Thanks [@christopherstyles](https://github.com/christopherstyles)! - Associations are declared as record fields, written once: `posts = hasMany(Post, { dependent: "destroy" })`, `author = belongsTo(User)`, `profile = hasOne(Profile)`, imported from the package. TypeScript infers each accessor's type, and association scopes are typed from their target. **Breaking:** `static associations = this.defineAssociations({...})` and the `declare posts: HasMany<typeof Post>` lines are gone. Move each association into a field, and drop its `declare` line.

- [`e3674a6`](https://github.com/forestfuture/d1-record/commit/e3674a6de6a642dc383b219886ee2e62bfd1def0) Thanks [@christopherstyles](https://github.com/christopherstyles)! - Attribute values are cast to their type when they're assigned or given to a bulk write, and in conditions. Only unambiguous values are accepted: `"false"`, `"0"` and `"off"` are `false` for a boolean, `"42"` is `42` for an integer, and an ISO-8601 string is a `Date`. Anything else throws `TypeError`: `"no"` for a boolean, `"12abc"` or `1.7` for an integer, a number for a string, a time without an offset. Before this, `"false"` was saved as `true`, and `"12abc"` was stored in an integer column.

  A condition value that can't be cast matches nothing, so `find("abc")` on an integer key throws `RecordNotFound`. In a condition, a number matches a string attribute as its digits (`7` finds `"7"`), as `find` does for a text key.

  An override that changes an attribute's `type` without giving a `default` now drops the generated default, so the column's own default applies.

- [`02094f5`](https://github.com/forestfuture/d1-record/commit/02094f5ec51676f25557dee8af67cc08ab04f627) Thanks [@christopherstyles](https://github.com/christopherstyles)! - Queries start from the Model, as in Rails: `User.find(id)`, `User.where(…)`, `User.create(…)`, `User.active()`, and every other Relation method as a typed static. With no setup they use the Model's binding (`static binding = "DB"`, written on your `ApplicationRecord`'s base class by `d1-record schema`). For a D1 Session, per-request `onQuery`, or tests outside a Worker, `withDatabase(connect(env.DB, { … }), fn)` gives a request its own database. `batch([...])` writes atomically on the current database. `db.model(X)` still works as before.

  Scopes are now declared one static each, as Rails' `scope :active, -> { … }`: `static active = this.scope((q) => q.where({ isActive: true }))`, replacing `static scopes = this.defineScopes({...})`. They inherit like any static.

- [`0f4848f`](https://github.com/forestfuture/d1-record/commit/0f4848f1ce64523a0f678f1a8421551d415a96e6) Thanks [@christopherstyles](https://github.com/christopherstyles)! - `onQuery` listeners see the bound values of filtered attributes as `"[FILTERED]"`, as Rails' logs do, and so do cast errors. `static filterAttributes` starts with Rails' default list (`passw`, `email`, `secret`, `token`, `_key`, `crypt`, `salt`, `certificate`, `otp`, `ssn`, `cvv`, `cvc`), matched against each attribute's snake_case name, so passwords, tokens, API keys and emails no longer reach your logs. Replace the list on your app's base class: `static override filterAttributes = [...Model.Base.filterAttributes, "iban"]`, or `[]` to filter nothing. D1 still gets the real values.

- [`4f48758`](https://github.com/forestfuture/d1-record/commit/4f4875802944d87fbe88dbc268fa4f367f4e2d1b) Thanks [@christopherstyles](https://github.com/christopherstyles)! - First release: a Rails-inspired Active Record for Cloudflare Workers and D1. Models with typed attributes, validations, callbacks, associations and change tracking; lazy, composable queries; atomic batches; and read-replica sessions. See the guide at https://docs.forestfuture.dev/d1-record/.

- [`dd95b62`](https://github.com/forestfuture/d1-record/commit/dd95b6214e1eebccd333741a9f12ffa2df5c9885) Thanks [@christopherstyles](https://github.com/christopherstyles)! - Bulk writes run when called, as in Rails: `await posts.deleteAll()` and `updateAll(…)` resolve to the number of rows (on `none()`, `0` without a query), and `insert`, `insertAll`, `upsert` and `upsertAll` to D1's `meta`. For `db.batch([...])`, use their `to…` forms (`toInsert`, `toUpdateAll`, `toDeleteAll`, …), as records use `toSave()`/`toDestroy()`. **Breaking:** `.run()` is gone. Drop it where a write ran on its own, and use the `to…` form where a write went into a batch.
